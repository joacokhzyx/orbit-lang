# ORBIT — EDITORIAL & BRAND LANGUAGE SYSTEM

Version 1.0 — Source of truth. From Joaquín, for Orbit.
Status: draft for review, not yet part of the public docs.

This file is the operating system for how Orbit speaks. If a line could belong to a crypto startup, a cyberpunk tool, or a "blazingly fast" framework, it fails here.

---

## 1. Brand essence

**Rule:** Orbit is an attempt to prove that servers and APIs shouldn't need so much energy to be fast.

Why: "Fast language" is generic. "Green language" invites greenwashing accusations. The essence must hold both halves: speed without waste, plus humility that it's still being proven.

Correct:
> Orbit is a programming language for servers and APIs, designed to do more with less.

Incorrect:
> Orbit is a next-gen, blazingly fast language that obliterates bottlenecks.

Difference: the first can be checked. Less of what? Less energy, less complexity, less to install. The second cannot be checked.

## 2. Brand philosophy

1. Scaling by adding consumption, compute, or parameters just because we can is bad engineering. It's clumsy.
2. Software is physical. "Digital" does not mean clean. Every request costs energy, usually from non-renewable sources.
3. No mainstream language was designed to be specifically efficient. They compete on benchmarks to show power, regardless of what they generate.
4. Doing more with less is respect — for the machine, for energy, for people without exceptional hardware.
5. Comfort is philosophical. If it needs giant dependencies to start a server, it's not elegant, even if it's fast.

Orbit is not an ecological project that makes a language. Orbit is an engineering project whose natural result is ecological. Lead with engineering, let planet follow.

Correct:
> We think it's clumsy to need so much to do so little. Orbit tries to need less.

Incorrect:
> Save the planet with Orbit, the eco-friendly green language.

## 3. Mission

Working formulation, humble ambition:

> I'm building Orbit to explore a simple idea: servers, APIs and microservices shouldn't need so much energy to be fast. We're still measuring how far it can go.

Never publish as fact: "Orbit reduces large-scale energy consumption."
Always publish as intention + evidence with machine, workload, and method recorded.

## 4. Editorial positioning

Against wasteful scaling and empty radical promises made with the same methods. For clear explanation and calm confidence.
Reference OpenAI for restraint and human accessibility, not for method. We admire what OpenAI started at scale and Google's invisible stability, but disagree with scaling by more energy. Study their clarity, counter their method.
Never AI-generic, crypto, cyberpunk, hacker, excessively futuristic, or exaggerating.

A senior who has seen 100 "10x faster" claims should think "this person measures honestly." A smart non-technical reader should think "this matters and I can trust it."

## 5. Audience

Primary: skeptical backend engineer. Wants curiosity, not hype. First feeling: curiosity about why it compiles fast, runs on little, needs no giant dependencies.
Secondary: intelligent non-technical reader. Wants trust. Should grasp importance without knowing throughput.

Never impress investors with adjectives. Never infantilize engineers to include outsiders.

Correct:
> Orbit compiles fast and needs little to run, so it stays fast even under load.

## 6. Voice

Strict rule for solo-author credibility:

1. **I / Joaquín** for opinion, intention, doubt: I think / I'm building / I'm testing / I don't know yet.
2. **Orbit** for technical fact: Orbit compiles to... / Port 3000 is already in use.
3. **We — forbidden for now.** No fake team. No Enthropy Labs mention in Phase 1.

Saying "we" with one author destroys trust. Saying "I" with modest hardware creates trust, because constraint proves principle.

Correct:
> I created Orbit because I didn't have an exceptional machine. I needed a language that needs little.

Incorrect:
> We at Enthropy Labs engineered a world-class solution.

## 7. Tone

Voice doesn't change. Tone shifts by situation. Base 6-7/10: precise but conversed.

- Homepage: calm, minimal.
- Docs: patient teacher. Direct you.
- GitHub: builder to builder. Commands early.
- Research: humble scientist. Numbers + method + limits.
- Changelog: factual, grateful.
- Errors: clear header + helpful body. Never blames you. Owns Orbit faults.
- Announcements: quiet. "Available" beats "Thrilled to announce revolution."

## 8. Personality

Curious like 15, disciplined like 40. Builder with little hardware, not funded founder. Explains without condescension. Says I don't know easily. Intelligence to transmit is clarity, not brilliance.

## 9. Writing principles

1. Explain simply. Sophistication is clear thinking, not sophisticated words.
2. Show observable. If you can't point to it, don't claim it.
3. Verbs over adjectives. Compiles, needs, stays beats blazing, superior, seamless.
4. One idea per sentence.
5. Helpfulness is motivation.
6. Own ignorance publicly.
7. Never make the reader decode metaphor to act.
8. Restraint is confidence.

## 10. Sentence architecture

Headlines short (3-6 words). Body fluid-explained, 15-22 words, cause-effect explicit.

> Orbit is a statically typed language for APIs and microservices. It compiles fast and needs little to run, so it stays fast even under load.

Active over passive. Second person for action. Contractions always (can't, doesn't, here's). No exclamation stacks.

## 11. Rhythm

Calm, even. Short headline pause, then longer explanatory wave.

> Do more with less.
> Orbit is a language for APIs and microservices. It compiles fast and needs little to run, so it stays fast even under load.
> In our initial test on a modest laptop, it handled N requests with M memory. Methodology here.

Read aloud. If you run out of breath, split. If it sounds like a trailer, calm it.

## 12. Vocabulary

Prefer plain, physical, checkable: light, little, less, more, fast, compiles fast, needs little, stays fast, simple, direct, clear, enough, waste, care, measure, try, change, run, build, test, still measuring, modest, small fix.

Energy words: energy, consumption, resources, waste, needs, costs, use. Avoid as identity: sustainable, green, eco-friendly unless with data. Ecological is result, vocabulary stays engineering.

User proposed "sustained superior performance" to replace "high-performance." Judgment: still generic. Translate to behavior: stays fast under load + number.

## 13. Forbidden vocabulary

Tier 1 — NEVER: obliterates, blazingly fast, game-changer, revolutionary, supercharge, disruptive, high-performance (naked), ultra-low latency (naked).
Tier 2 — AVOID: next-gen, cutting-edge, world-class, seamless, unlock, elevate, power your, engineered for.
Tier 3 — ONLY WITH NUMBER + METHOD: fast, faster, efficient, performant, scalable, throughput. Adjective must be followed by context.

Top 3 to ban forever: obliterates, revolutionary / game-changer, blazingly fast / supercharge.

Correct:
> In our initial test, Orbit handled N requests with M memory.

Incorrect:
> Orbit obliterates bottlenecks with blazing revolutionary performance.

## 14. Metaphorical language

Decision: A with very light B. Name Orbit already carries metaphor: what orbits stays in motion without wasting more. Don't explain it.
Elsewhere zero ships as identity. Allowed sparingly in relief moments only (install success, 404), never in blocking error headers, benchmarks, or core docs. Max 1 per 10 messages.

Header (no metaphor):
> Port 3000 is already in use. Change it in X.orb and try again.

Body mix (helpful + warm):
> Tip: run `orbit ports` to see what's free. Small fix — you'll be running in seconds.

Rare orbital body, non-blocking only:
> Adjust and relaunch.

Incorrect:
> This orbit is already occupied by another ship in 3000 port!!!

Why: grammar, forces decoding under stress, hard for non-natives, irritating on tenth sight.

## 15. Technical language

Name the thing, what it does, why it matters, in that order. No zero-copy / high-concurrency without plain translation. Prefer example over definition.

Correct:
> Orbit compiles directly to a single binary. You don't install giant dependencies to start a server. `orbit run X.orb` is enough.

## 16. Marketing language

Marketing = clarity + proof. Allowed: try, read, build, measure, see. Forbidden: unlock, elevate, supercharge, disrupt, join the revolution, don't get left behind.

CTA primary: Read the docs. Secondary: Try Orbit. Tertiary: Star on GitHub.

Announcement template:
> Orbit 0.X is available. It does X, fixes Y. It still can't do Z. Docs here.

## 17. Human language

Human is not emotional adjectives. It's curiosity, empathy at 3am, humility, responsibility, helpfulness. Motivational = here's exactly how to continue. Pretty = easy to scan.

Correct:
> Port 3000 is already in use. Change it in X.orb and try again. Tip: run `orbit ports` to see what's free.

Incorrect:
> Oopsie!!! You broke it!! You've got this, superstar!!!

Humor: good light humor allowed, never when Orbit is at fault, never in blocking errors or benchmarks. If Orbit broke it, be serious, apologize plainly, fix.

Correct ownership:
> You're right, I hadn't seen it that way. I'm fixing it. Here's a workaround for now.

## 18. Claims and evidence

NEVER: Orbit is faster than Rust / Go.
ALWAYS: In our initial test on [exact machine], Orbit handled N requests with M memory. Latency p99 L. Method here. Still measuring.

Every number needs machine, workload, version, date, config, failures included. Intention language when no data: Our goal is... / I'm testing whether...

## 19. Handling uncertainty

Default:
> I don't know yet. I'm measuring. Here's what I'm testing next.

Never hide with silence. Publish limits and "What Orbit is not yet." Publish bad numbers too.

## 20. Competitive language

Never name languages to claim superiority. Engineering critique, not moral denunciation. Say clumsy, wasteful, needs so much — not irresponsible polluters.

Correct:
> Many languages optimize for peak benchmark power. That often needs more memory and energy to stay fast. Orbit tries a different tradeoff.

## 21. Website language

Headline: Do more with less.
Subhead: Orbit is a statically typed language for APIs and microservices. It compiles fast and needs little to run, so it stays fast even under load.
Proof strip: orbit run with no giant deps / compiles in X on modest laptop / N req/s with M memory + link.
Founder note in I-voice. No Enthropy Labs Phase 1. Footer: Built by Joaquín — Argentina. Early research.

## 22. Documentation language

Patient colleague, direct you, contractions. Pattern: What this does → Why it matters → Try this (code) → If it fails (exact fix). Define jargon plainly on first use.

## 23. GitHub language

Builder to builder. Code above poetry. README order: one-line plain → quickstart → numbers + method + limits → roadmap / Not yet → how to file issue kindly. Own bugs, thank specifically.

## 24. Research language

Question, method, machine, version, results, limits, next test, reproduce link. Hedges allowed. Never proves, guarantees, revolutionary breakthrough.

## 25. Announcement language

Quiet. Orbit 0.X is available. It does X. Fixes Y. Still can't do Z. Docs link. If it breaks, file here, I read everything.

## 26. Headline system

Primary (philosophy): Do more with less.
Secondary (concrete): Fast to compile. Light to run. / Needs little to stay fast.
Rule: abstract headline must be followed by concrete subhead. Never Tier 1 words.

## 27. Subheadline system

Formula: what it is + what it needs + what it stays + proof hint. 1-2 sentences, 15-28 words.

> Orbit is a statically typed language for APIs and microservices. It compiles fast and needs little to run, so it stays fast even under load.

## 28. CTA system

1. Read the docs — primary, low pressure.
2. Try Orbit — secondary.
3. Star on GitHub — tertiary.
Sentence case, no exclamation, no urgency.

## 29. Error and system language

Two layers:
Header (always clear, no metaphor, no Oh!, no emoji): Fact + file + action.
> Port 3000 is already in use. Change it in X.orb and try again.
Body (optional, helpful first, warmth second, orbital max 5 words): Tip + warm line.
> Tip: run `orbit ports` to see what's free. Small fix — you'll be running in seconds.
Success: quiet confirmation + next step.
When Orbit at fault: zero humor, own it, workaround, apologize for lost time.

## 30. Long-form writing

Start with observation from building, then idea, evidence, limit, invitation. I-voice, short paragraphs. Structure: Problem seen → What I tried → What happened → What I don't know → What I'm testing next.

## 31. Short-form writing

1 idea, 1 proof or question, link.
Correct: Orbit 0.3 compiles 20% faster on my laptop (8GB). Still measuring energy. Method here. What would you test?

## 32-34. Examples / Anti-examples / Before-after

Good Orbit paragraph:
> I'm building Orbit because I didn't have much. No exceptional PC, no big budget. I needed a language that needs little to be fast. It compiles fast and stays fast without giant dependencies, so you can run a real API from a modest machine. I'm still measuring energy per request. I'll publish even when numbers are bad.

Never sound like this:
> Orbit is a world-class next-gen high-performance ultra-low latency solution that seamlessly unlocks disruptive power and obliterates bottlenecks. Join the revolution!!!

Before → After:
- "high-performance..." → "compiles fast, needs little, stays fast under load + number"
- "Oh! orbit occupied by ship!!!" → "Port 3000 is already in use. Change it in X.orb and try again."
- "Sustained superior performance" → "Stays fast under load. N req/s, p99 L, M memory on [machine]."
- "Save planet with green Orbit!" → "Less energy per request means less cost and less waste."

## 35. Editorial checklist

1. Could a tired dev act without decoding?
2. Every adjective followed by number/method or removed?
3. I for doubt/intention, Orbit for fact, no fake we?
4. Contractions? No exclamation stack? No emoji?
5. No Tier 1 words? No superiority?
6. Number has machine + version + date + method + failures?
7. Uncertainty said plainly?
8. No Enthropy Labs Phase 1? No naming competitors?
9. Orbital 0 in header, max 1 light in body?
10. Read aloud calm? Would Joaquín say this to a senior without embarrassment?

## 36. Common failure modes

Hype relapse, cute error overload, fake we, greenwashing drift, superiority jab, motivational cheese, hiding bad numbers, blaming user with humor. Fix each by returning to observable + method + owning.

## 37. Rules for future writers and AI systems

Never invent team, funding, numbers. Never mention Enthropy Labs until Phase 2. Default I/Orbit voices. English with contractions. Headline Do more with less. + concrete subhead. CTA Read the docs. Errors header fact+fix, body tip+warmth. Every claim needs method. Forbidden tiers enforced. When in doubt choose calmer, shorter, more honest.
